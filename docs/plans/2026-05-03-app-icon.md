# Add the App Icon to Quiet Whisper

## Context

Quiet Whisper is a SwiftUI macOS app (single-window, not menu-bar) currently shipping without an app icon — the Finder/Dock show a generic placeholder. A complete brand kit was just delivered to `~/Downloads/brand/` with the squircle-masked icon pre-rendered at every size Apple expects (`AppIcon.iconset/`), plus the canonical SVG, social variants, and a build script. The project already has `ASSETCATALOG_COMPILER_APPICON_NAME = AppIcon` wired in `project.pbxproj` (xcodegen sets it by default), but there is no asset catalog on disk yet — `QuietWhisper/Resources/` is referenced in [project.yml](../../QuietWhisper/project.yml) but doesn't exist. We just need to drop a properly-formatted asset catalog into that path and re-run xcodegen.

## Approach: Asset Catalog (`Assets.xcassets/AppIcon.appiconset`)

The brand folder also includes a `build-icns.sh` path (rename `-at2x` → `@2x`, run `iconutil`, get `AppIcon.icns`, then set `CFBundleIconFile`). I'm not using it — modern SwiftUI/Xcode targets standardize on the asset catalog, the build setting is already in place, and asset catalogs cleanly support future additions (dark/tinted variants, additional images). The icns route would mean adding `CFBundleIconFile` to Info.plist and dropping a binary into Resources, with no upside.

## Files to regenerate (no manual edit)

- **`QuietWhisper/QuietWhisper.xcodeproj/project.pbxproj`** — re-run `xcodegen generate` from the `QuietWhisper/` directory. xcodegen auto-discovers the new `Assets.xcassets` under the configured resources path and adds it to the target. The `ASSETCATALOG_COMPILER_APPICON_NAME = AppIcon` build setting is already in place, no project.yml change needed.

## Brand source files

Copy the entire `~/Downloads/brand/` tree into `design_handoff_quiet_whisper/brand/` so all design assets stay together. This is the canonical source-of-truth for the icon (SVGs, `build-icns.sh`, the full pre-rasterized iconset, social variants, README). The PNGs the build actually consumes are duplicated into `Assets.xcassets/AppIcon.appiconset/` — yes, the PNGs end up in two places, but the asset catalog needs Apple's exact filenames (`@2x`) and lives under the build target's resources path; the brand folder preserves the canonical kit unchanged.

The brand README references `brand/build-icns.sh` and `brand/AppIcon.iconset/` paths that won't resolve from the new location. Update README to use paths relative to its own location so the script still works in place.

## Out of scope (intentionally)

- **`menu-bar.svg`** — [QuietWhisperApp.swift:2](../../QuietWhisper/QuietWhisper/QuietWhisperApp.swift) explicitly says "no menubar item". Skip until/unless the app gains one.
- **In-app `PaperIcon` set** — those are separate UI chrome icons in [Theme/Icons.swift](../../QuietWhisper/QuietWhisper/Theme/Icons.swift); the brand's `glyph-*.svg` and `mark-on-*.svg` are marketing assets, not app chrome. AGENTS.md is explicit: "Do not use SF Symbols. The icons are deliberately custom."
- **Document type icons, dark-variant AppIcon, tinted icon for macOS Sonoma+** — none requested. The asset catalog format leaves room to add these later.

## Verification

1. From `QuietWhisper/`: `xcodegen generate`. Confirm pbxproj diff adds an `Assets.xcassets` reference under the Resources group.
2. `xcodebuild -project QuietWhisper.xcodeproj -scheme QuietWhisper build` (or open in Xcode and ⌘B). Confirm no asset-catalog warnings in the build log.
3. Run the app (⌘R). Look for the cream-on-ink mark in:
   - The Dock (while running)
   - `Cmd-Tab` switcher
   - About panel (`QuietWhisper › About QuietWhisper`)
   - Finder's Get Info on the built `.app` (right-click in `~/Library/Developer/Xcode/DerivedData/.../QuietWhisper.app`)
4. Run the existing test suite (`xcodebuild test`) to confirm nothing else broke. The release workflow at [.github/workflows/release.yml](../../.github/workflows/release.yml) should produce a zipped `.app` whose Finder thumbnail shows the new icon.
