# Plan: GitHub Actions CI + downloadable build for Quiet Whisper

## Context

The repo has no `.github/` directory and no CI. The user wants two things on GitHub:

1. **Tests run in CI** on every push / PR.
2. **The built `.app` is downloadable** from GitHub — both as an Actions artifact on every push to `main` (quick internal access) and as a public asset on a GitHub Release (shareable, no login).

Code signing: unsigned / ad-hoc (no paid Apple Developer account). End users will need a one-time Gatekeeper bypass (right-click → Open) — this is acceptable for now.

Key facts driving the design:
- **xcodegen-based**: `QuietWhisper.xcodeproj` is generated from `QuietWhisper/project.yml`. The project file *is* checked in, but the canonical practice in this repo is to regenerate it. CI will regenerate to be safe (also future-proofs against contributors who forget).
- **Test target exists but is empty** ([QuietWhisper/QuietWhisperTests/](QuietWhisper/QuietWhisperTests/) has no source files). To make `xcodebuild test` succeed reliably, we need at least one stub test file so the bundle builds and runs.
- **WhisperKit (SPM)** is the only external dep. `Package.resolved` is gitignored, so SPM resolution happens fresh on CI; we'll cache `SourcePackages` to keep this cheap.
- **Code signing**: with `ENABLE_HARDENED_RUNTIME: YES` and entitlements set in [project.yml](QuietWhisper/project.yml), the build needs at minimum ad-hoc signing (`CODE_SIGN_IDENTITY=-`). We pass that explicitly via xcodebuild flags so no certificates are required on the runner.
- **Runner**: `macos-14` (Sonoma) — matches the deployment target and ships with Xcode 15.x (SwiftData support).

## Workflow 1 — `.github/workflows/ci.yml` (tests)

**Triggers**: push to any branch, pull_request to `main`.

**Job** (single, on `macos-14`):
1. `actions/checkout@v4`
2. Cache `~/Library/Developer/Xcode/DerivedData/QuietWhisper-*/SourcePackages` keyed on `project.yml` hash
3. `brew install xcodegen` (cheap; ~20s)
4. `cd QuietWhisper && xcodegen generate`
5. Run tests:
   ```
   xcodebuild test \
     -project QuietWhisper/QuietWhisper.xcodeproj \
     -scheme QuietWhisper \
     -destination 'platform=macOS' \
     -configuration Debug \
     CODE_SIGN_IDENTITY=- \
     CODE_SIGNING_REQUIRED=NO \
     CODE_SIGNING_ALLOWED=NO \
     | xcbeautify
   ```
   (`xcbeautify` is for readable logs; `brew install xcbeautify` in the same step. Falls back to raw output if pipe fails — `set -o pipefail`.)

`pull_request` runs are required to gate merges into `main`; the user can wire that up as a branch protection rule later (manual GitHub setting, not part of this plan).

## Workflow 2 — `.github/workflows/release.yml` (downloadable build)

**Triggers**:
- `push` to `main` → build, upload as Actions artifact (90-day retention).
- `push` of tag matching `v*` (e.g., `v0.1.0`) → build, then create a GitHub Release and attach the zipped `.app`.
- `workflow_dispatch` for manual runs.

**Job** (single, on `macos-14`):
1. Checkout, cache, install xcodegen + xcbeautify (same as ci.yml — could be factored into a reusable composite action later, but YAGNI for now).
2. `xcodegen generate`.
3. Release build:
   ```
   xcodebuild build \
     -project QuietWhisper/QuietWhisper.xcodeproj \
     -scheme QuietWhisper \
     -configuration Release \
     -destination 'platform=macOS' \
     -derivedDataPath build \
     CODE_SIGN_IDENTITY=- \
     CODE_SIGNING_REQUIRED=NO \
     CODE_SIGNING_ALLOWED=YES \
     | xcbeautify
   ```
   (Ad-hoc `-` signature is required because the entitlements file references hardened runtime; without `-`, the build fails. With `-`, the .app runs locally but Gatekeeper still flags it on first download — expected.)
4. Zip the .app with `ditto` (preserves bundle structure):
   ```
   cd build/Build/Products/Release
   ditto -c -k --sequesterRsrc --keepParent QuietWhisper.app QuietWhisper.zip
   ```
5. **Always**: `actions/upload-artifact@v4` with name `QuietWhisper-${{ github.sha }}` and the zip.
6. **On tag push only** (`if: startsWith(github.ref, 'refs/tags/v')`): create the Release with `softprops/action-gh-release@v2`:
   - `files: build/Build/Products/Release/QuietWhisper.zip`
   - `generate_release_notes: true`
   - `draft: false`, `prerelease: false`
   - Release name: tag name (e.g. `v0.1.0`)
   - Body includes a one-line note about Gatekeeper: "First launch: right-click the .app → Open (one-time, because the build is unsigned)."

Permissions: `contents: write` on the release job so `gh` / the action can create the Release.

## Stub test — `QuietWhisper/QuietWhisperTests/SmokeTests.swift`

A minimal `XCTestCase` so the test target produces a runnable bundle. Just one trivial assertion confirming the host app can be linked.

```swift
import XCTest
@testable import QuietWhisper

final class SmokeTests: XCTestCase {
    func testHostAppLinks() {
        XCTAssertTrue(true)
    }
}
```

After creating this file, run `cd QuietWhisper && xcodegen generate` once locally so the project picks it up (the regenerated project.pbxproj will be committed). CI will also regenerate, so this is mainly for the local dev experience.

## Notes & explicit non-goals

- **No notarization.** Per user choice. Re-evaluate when there's an Apple Developer account.
- **No matrix builds.** macOS 14 only.
- **No `Package.resolved` change.** Currently gitignored; CI is OK with re-resolving on cache miss. (Worth revisiting later for fully reproducible builds, but out of scope here.)
- **No branch protection rules** — those are configured in GitHub UI, not in code.
- **No version bumping automation.** Tags are created manually (`git tag v0.1.0 && git push --tags`) when the user wants to cut a release. The version in [project.yml](QuietWhisper/project.yml) (`CFBundleShortVersionString`) is a separate field; I'm not auto-syncing it to the tag in v1 of this plan — easy follow-up if desired.

## Execution flow (branch + PR)

All changes land on a feature branch and ship as a single PR:

1. **Branch**: create `ci/github-actions` off `main`.
2. **Commit 1 — plan**: copy this plan file into `docs/plans/ci-and-release-workflow.md` and commit (`docs: plan for CI + downloadable build`). Push the branch immediately so the PR can be opened early.
3. **Commit 2 — implementation**: add `SmokeTests.swift`, regenerate the xcodeproj (`cd QuietWhisper && xcodegen generate`), and add `.github/workflows/ci.yml` + `.github/workflows/release.yml`. Single commit (`ci: add test + release workflows`).
4. **Push** the branch.
5. **Open PR** against `main` via `gh pr create`. Title: `Add GitHub Actions: tests + downloadable build`. Body summarizes the two workflows, the stub test, and links to the plan doc; includes a Test plan checklist (CI run on the PR, manual `workflow_dispatch` of release.yml after merge, tag a release to verify the public download).
6. Return the PR URL.

I will **not** push tags or trigger a release as part of this work — the user does that manually after merging the PR.

## Verification

Local-ish checks before relying on CI:
1. `cd QuietWhisper && xcodegen generate` succeeds.
2. `xcodebuild test -project QuietWhisper.xcodeproj -scheme QuietWhisper -destination 'platform=macOS' CODE_SIGN_IDENTITY=- CODE_SIGNING_REQUIRED=NO CODE_SIGNING_ALLOWED=NO` runs the stub test and passes.
3. `xcodebuild build -configuration Release ... -derivedDataPath build CODE_SIGN_IDENTITY=-` produces `build/Build/Products/Release/QuietWhisper.app`.
4. `ditto -c -k --sequesterRsrc --keepParent QuietWhisper.app QuietWhisper.zip` produces a zip; unzip it elsewhere and confirm the .app launches (right-click → Open the first time).

CI checks after pushing:
1. Open the repo's **Actions** tab → CI workflow runs and passes on `main`.
2. Push a no-op commit → release.yml runs → an artifact named `QuietWhisper-<sha>` appears on the run, downloadable as a zip.
3. Tag a release: `git tag v0.1.0 && git push origin v0.1.0` → release.yml runs the tag-only step → a new entry appears under **Releases** with `QuietWhisper.zip` attached and a public download URL.
4. Download the public URL in a private/incognito window (no GitHub login) to confirm anyone can grab it.
